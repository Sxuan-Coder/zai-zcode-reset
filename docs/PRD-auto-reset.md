# PRD —— 重置卡到期自动重置（Auto Reset on Card Expiry）

> 版本：v1 草案（2026-10-28，需求已与 Owner 确认）
> 状态：待评审 → 通过后进入实施

---

## 1. 背景与问题

上游 Coding Plan 的重置能力以**重置机会（opportunity，下称"重置卡"）**形式发放：账号申领后会得到带 `expire_at`（毫秒截止时间）的卡，status 接口的 available 列表里就是这些**已申领、未消耗、未过期**的卡；`use` 接口消耗一张卡完成重置，过期未用则作废。

当前平台的卡只能由成员在面板上手动点击消耗。实际使用中经常发生：**账号额度确实被消耗了，但没人管这张卡，到期作废，额度白白没换回来。**

## 2. 目标

卡即将到期时，若它还没被用掉、且账号对应窗口的额度确实被消耗过（重置有收益），由系统**自动用卡执行重置**，把本要作废的卡换成额度。

## 3. 术语与数据来源

| 术语 | 含义 | 数据来源 |
| --- | --- | --- |
| 重置卡 | 上游已申领、未消耗的重置机会，带 `expire_at` | `GET /api/v1/coding-plan/reset/status` 的 `available_five_hour_resets` / `available_week_resets` |
| 截止时间 | 卡的 `expire_at`（毫秒） | 同上 |
| 窗口已用占比 | 5 小时窗口 = `TOKENS_LIMIT unit=3` 的 `percentage`；周窗口 = `TOKENS_LIMIT unit=6` 的 `percentage` | `GET /api/monitor/usage/quota/limit`（只读，不耗额度） |
| 窗口剩余占比 | `100 − percentage` | 计算值 |
| FIVE_HOUR 卡 / WEEK 卡 | 消耗时 `reset_type` 分别为 `FIVE_HOUR` / `WEEK` 的卡 | status 列表区分 |

## 4. 核心规则（已与 Owner 确认的 4 项决策）

对每个**启用的上游账号**，后台定时任务每 30 秒扫描一次，对 status 返回的每张未过期卡判断：

```
触发条件（全部满足才自动用卡）：
  ① 卡未被消耗（在 available 列表中，天然成立）
  ② 处于触发窗口：expire_at − 提前量 ≤ 当前时间 < expire_at
  ③ 额度确实被消耗过：该卡对应窗口的 剩余占比 < 阈值
     · FIVE_HOUR 卡 → 检查 5 小时窗口（unit=3）
     · WEEK 卡      → 检查周窗口（unit=6）
     · 默认阈值 90%：剩余 < 90%（即已用 > 10%）= "用过了" → 自动重置
     · 剩余 ≥ 阈值 = 几乎没用过，重置无收益 → 不动，让卡自然过期
```

| 决策点 | 结论 |
| --- | --- |
| 触发口径 | **剩余低于阈值才重置**；剩余 ≥ 阈值不动，让卡过期 |
| 配置粒度 | **全局默认 + 按账号覆盖**（账号不设置覆盖则用全局） |
| 卡类型 | **FIVE_HOUR 与 WEEK 都处理，阈值分开配置**（各自检查各自窗口） |
| 平台配额 | **不占用**用户的每日/每周重置次数（卡本来要作废），日志标记来源 |

### 4.1 派生行为

- **用量是动态评估的**：每个 tick 都重新拉取用量。窗口内剩余从 95% 掉到阈值以下（用户还在持续消耗）时，会开始触发。
- **多张同类卡不会连环消耗**：用掉一张卡后窗口重置、剩余回到高位，其余同类卡自然不再满足条件 ③；等额度再次被消耗且又有卡进窗口才会再触发。
- **与手动重置互不干扰**：成员在窗口内手动用卡后，下个 tick 卡已从 available 消失，自动流程自然跳过。极端并发下（手动与自动同时 use 同一张卡）上游会拒绝后到的一次，按失败日志记录，不产生重复重置。

## 5. 配置模型

### 5.1 全局默认配置

存于 `db.json` 新增 `settings.auto_reset` 节，首次启动播种默认值：

| 字段 | 类型 | 默认 | 约束 | 说明 |
| --- | --- | --- | --- | --- |
| `enabled` | bool | `false` | — | 总开关，默认关闭，管理员显式开启 |
| `lead_minutes` | int | `10` | 1–60 | 提前量（分钟），到期前多久开始评估触发 |
| `five_hour_threshold` | int | `90` | 50–99 | 5 小时卡的剩余占比阈值（%） |
| `week_threshold` | int | `90` | 50–99 | 周卡的剩余占比阈值（%） |

### 5.2 账号覆盖

`UpstreamAccount` 新增可选字段 `auto_reset`（同上四字段的**整组覆盖**；未设置 / null = 跟随全局）。不做字段级合并——要么整组覆盖，要么完全跟随全局，保证配置可读。

生效优先级：`账号覆盖（若设置）> 全局默认`；账号 `enabled=false` 时该账号完全不参与扫描。

### 5.3 管理接口（均记审计日志）

| 接口 | 说明 |
| --- | --- |
| `GET /api/admin/auto-reset` | 返回全局配置 + 各账号生效配置（含"覆盖来源"标注） |
| `PUT /api/admin/auto-reset` | 更新全局配置（校验范围约束） |
| `PATCH /api/admin/accounts/{id}` | 扩展 `auto_reset` 字段：传对象 = 设置覆盖，传 `null` = 清除覆盖 |

## 6. 调度器行为

- 新增 `internal/autoreset` 包，`main.go` 启动单个后台 goroutine，随进程优雅退出；每 30 秒一个 tick，**顺序**处理各账号（无并发竞争）。
- 每个 tick 对每个启用账号：解密令牌 → `status` 拿可用卡 → 对处于触发窗口的卡拉 `quota/limit` 评估条件 ③ → 满足则生成幂等键调 `use`。
- **重试**：窗口内失败（网络 / 429 / 业务错误）下个 tick 重试（约 30s 间隔），**同一张卡的所有重试复用同一个幂等键**；直到成功或 `expire_at` 已过。到期仍未成功 → 记一条最终失败日志（`error_kind=auto_expired`）。
- **不写全局冷却**：自动重置的失败不影响成员手动重置（不调用 `SetCooldown`），重试节奏由调度器自身控制。
- **不预占配额**：不调用 `quota.Reserve` / `Rollback`。
- **不申领新机会**：只消耗 status 里已有的卡，绝不调 `opportunity` 接口。
- **重启恢复**：调度状态只在内存。重启后下个 tick 重新拉 status：已用掉的卡已从列表消失（不会重复消耗）；仍在窗口内的未处理卡重新进入评估。每张卡的处理状态以 `accountID|resetType|expireAt` 为键在内存去重，成功的卡不再处理。
- **日志降噪**：重试过程不逐条落日志，仅"成功"与"最终放弃（到期）"各一条；账号级错误（令牌解密失败、status / 用量查询失败）按账号限频落日志（每账号每小时至多一条，服务端日志不限）。

## 7. 日志与可见性

- `ResetLog` 新增 `trigger` 字段：`manual`（默认，兼容旧行）/ `auto`。
- 自动重置日志：`Username` 记录该账号绑定的用户（无绑定则为空），`IP` 记为 `system`，成功时 `error_kind` 为空，失败时为 `auto_*` 系列。
- 管理后台 → 日志页：重置日志增加"自动/手动"标记列。
- 成员 → 记录页：自动重置记录同样展示（若账号绑定到该用户则可见；共享默认账号的场景以管理端日志为准）。
- 管理后台新增**「自动重置」页面**：全局配置表单（开关 / 提前量 / 两类阈值）+ 按账号覆盖配置区块（列出各账号当前生效值与来源），保存即生效，无需重启。

## 8. 边界情况

| 场景 | 行为 |
| --- | --- |
| `quota/limit` 拉取失败或找不到对应窗口数据 | 本 tick 无法评估 → 跳过，下个 tick 重试（保守，不盲动） |
| 账号令牌解密失败 / status 失败 | 该账号本 tick 跳过，记一条失败日志（每卡每窗口一次） |
| 服务重启落在触发窗口内 | 下个 tick 补上评估，卡仍在就正常处理 |
| 卡已过期出现在列表（理论不应发生） | 按 `validOpportunities` 同样规则过滤，不处理 |
| 服务器时钟偏差 | 卡时间与当前时间均为毫秒时间戳比对，依赖服务器 NTP 准确（部署注意事项，README 补充） |
| 旧数据迁移 | `db.json` 无 `settings` 节 → 用默认值；旧 reset.jsonl 无 `trigger` → 前端按 `manual` 展示 |

## 9. 非目标（v1 不做）

- 不做通知推送（邮件 / Webhook / 站内信）。
- 不做按用户粒度的配置（配置只有全局与账号两层）。
- 不自动申领重置机会（不调 `opportunity`，只"抢救"已申领的卡）。
- 不持久化调度器内部状态（重启即重新评估，见第 6 节）。

## 10. 验收标准

1. **单元测试**：阈值判定（含边界值）、全局/覆盖配置合并、触发窗口计算、多卡去重。
2. **Mock 联调**（`MOCK_UPSTREAM=true`）：构造临期卡 + 高用量 → 自动触发成功且日志正确；低用量 → 不触发；到期前持续失败 → 只有一条 `auto_expired` 日志。
3. **真实实测**（`127.0.0.1:8788`，data-prod 真实令牌）：验证真实 status / quota/limit / use 链路，**通过后才允许构建并推送镜像**。
4. 兼容性：升级后旧数据可读、旧日志正常展示、默认配置下（开关关闭）行为与现状完全一致。
